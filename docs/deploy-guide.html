Publishing Ahd

How to go from the project folder on your computer to an app people can install: download links on GitHub, the Microsoft Store, and Linux (terminal, AppImage and Flathub). Follow the steps in order.

Q

Is GitHub needed?

No law or store requires GitHub, but it is by far the easiest route, and without it several things get harder:

  • Windows installers without a Windows PC. The project includes a GitHub Actions workflow that builds the Windows and Linux installers on GitHub's own machines, for free for public projects.
  • The GPL licence. Ahd is GPL-3.0: anyone who gets the app must be able to get its source code. A public GitHub repository does that.
  • Download links. GitHub Releases host the installers with permanent links, which the Microsoft Store (EXE/MSI route) needs.
  • Flathub. The app ID io.github.<you>.Ahd is tied to a GitHub account. Without GitHub you would need your own domain name for the ID.

Without GitHub you would need a Windows PC to build, your own website to host the files, and a domain for Flathub.

1

Create the GitHub account

  1. Open github.com/signup and create a free account.
  2. Choose the username carefully. It becomes part of the app ID and of every link: io.github.mohamedamineam.Ahd and github.com/mohamedamineam/ahd. Short, lowercase, and without dashes is simplest (Flathub turns a dash into an underscore in the ID).
  3. Turn on two-factor authentication: profile picture → Settings → Password and authentication. GitHub asks for it anyway before you can publish code.
  4. Done: the project now uses the username mohamedamineam everywhere (app ID io.github.mohamedamineam.Ahd, links, catalogue address).

Put the code online

Do this in the terminal on your Linux Mint computer, once. The GitHub CLI (gh) handles the login and creates the repository for you.

Terminal · install the tools

Terminal · log in

After this, github.com/mohamedamineam/ahd shows the project. Two optional touches on the repository page:

  • Settings → General → Social preview: upload branding/png/github-social-preview-1280x640.png.
  • About (gear icon on the right): add a short description and the topics prayer-times, islam, quran.

Build the installers on GitHub

A release starts when a version tag is pushed. GitHub then builds everything on its own Windows and Linux machines (usually 15–30 minutes) and prepares a draft release that only you can see.

Terminal · start release 0.1.0
cd "/media/iamiinne/SSD 2/Ahd"
git tag v0.1.0
git push origin v0.1.0
  1. Follow the build in the repository's Actions tab (workflow “Release”). A red cross means a step failed; send Claude the error text.
  2. Open Releases → the draft Ahd v0.1.0. It contains:
    • Ahd_0.1.0_x64-setup.exe — Windows installer (per user, no administrator rights)
    • Ahd_0.1.0_x64_en-US.msi — Windows installer for managed PCs
    • Ahd_0.1.0_amd64.deb — Debian, Ubuntu, Linux Mint
    • Ahd-0.1.0-1.x86_64.rpm — Fedora, openSUSE
    • Ahd_0.1.0_amd64.AppImage — any Linux distribution
    • SHA256SUMS — checksums to verify the downloads
  3. Download and test them (a Windows PC or virtual machine for the .exe), then click Edit → Publish release. The download links are now public and permanent.
Windows warning on first run

Without a code-signing certificate, Windows SmartScreen shows “Windows protected your PC” for the downloaded installer (users click “More info” → “Run anyway”). The Microsoft Store route in step 7 avoids this.

Linux: installing from the terminal

What users type after downloading from the release page (you can copy these into the release notes):

Debian · Ubuntu · Linux Mint
sudo apt install ./Ahd_0.1.0_amd64.deb
# remove later with: sudo apt remove ahd
Fedora · openSUSE
sudo dnf install ./Ahd-0.1.0-1.x86_64.rpm
Any distribution · AppImage
chmod +x Ahd_0.1.0_amd64.AppImage
./Ahd_0.1.0_amd64.AppImage
Check a download
sha256sum -c SHA256SUMS --ignore-missing

Flathub, the Linux app store

Flathub apps appear in the software centres of Linux Mint, Fedora, Ubuntu (with Flatpak) and others. Its rules that matter here:

  • Open-source apps are built from source by Flathub, offline. The recipe (manifest) is ready at packaging/flatpak/io.github.mohamedamineam.Ahd.yml; two lists of dependencies are generated for each release.
  • The repository github.com/mohamedamineam/ahd must exist and match the app ID.
  • The app description file must validate (it does: packaging/linux/io.github.mohamedamineam.Ahd.metainfo.xml).
  1. Publish the first GitHub release (step 4).
  2. Fork github.com/flathub/flathub, make a branch new-pr, add the manifest and the generated files, and open a pull request. The exact commands are in docs/RELEASE_LINUX.md.
  3. Flathub reviewers test it and comment; after approval the app is live and each later release is a small pull request.

Microsoft Store

Create the developer account

  1. Open storedeveloper.microsoft.com and sign in with a Microsoft account.
  2. Choose Individual. Registration is free for individual developers since September 2025; you verify your identity with an ID document and a selfie. Company accounts pay a one-time fee.
  3. In Partner Center: Apps and games → New product, choose the package type (below), and reserve the name Ahd. The Arabic name عهد goes in the Arabic store listing.

Choose how to submit

Code-signing certificateNot needed: the Store signs itRequired, from a trusted authority (self-signed is refused)
CostFreeSignPath (free for open source, on approval) or Azure Trusted Signing (monthly fee)
Updates for usersDelivered by the StoreThe app must update itself (enable the built-in updater)
What you uploadA .msix fileA permanent link to the installer (e.g. the GitHub release asset) and the silent switch /S
Needs a Windows PCYes, once per release, to convert the installerNo

MSIX route, step by step

  1. In Partner Center, create the product as MSIX or PWA app. Open Product management → Product identity and note Package/Identity/Name and Package/Identity/Publisher (it starts with CN=).
  2. On a Windows 10/11 PC (a clean virtual machine is best), install MSIX Packaging Tool from the Microsoft Store.
  3. Choose Application package → Create package on this computer → installer Ahd_0.1.0_x64-setup.exe with installer arguments /S.
  4. Enter the package name and publisher exactly as in Partner Center, version 0.1.0.0, then finish the capture and create the .msix. You do not need your own certificate for a Store submission.
  5. Start a submission and upload the .msix under Packages.

The rest of the submission (both routes)

  • Pricing and availability: Free, all markets.
  • Properties: category Lifestyle (or Utilities & tools); privacy policy URL from step 3.
  • Age ratings: answer the questionnaire (no violence, no purchases, no user chat); an app like this usually gets the lowest age rating.
  • Store listing (English and Arabic): description from the README, screenshots from docs/screenshots/store-*.png (1920×1200), store logos from step 8.
  • Submit. Certification usually takes a few days; you get an email with the result.
Worth testing on the MSIX version

“Start with Windows” in an MSIX package needs a startup entry in the package manifest. Check it after conversion; Claude can add a ready-made MSIX manifest to the project if needed.
